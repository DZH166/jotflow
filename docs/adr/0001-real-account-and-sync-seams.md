# ADR 0001：真实账号与同步接缝

## 状态

已接受

## 背景

小董随心录需要从单浏览器本地工具升级为真实账号系统。账号之间必须完全隔离，用户登录后保持会话，离线时仍能记录，联网后自动同步。当前应用把界面、localStorage 和 IndexedDB 读写集中在 `src/main.ts`，直接接入云端会把认证、同步和页面逻辑混在一起。

## 决策

### 领域归属

- Supabase Auth 的用户 ID 是账号的稳定归属 ID。
- 每个云端记录都必须带 `owner_id`，数据库通过 Row Level Security 保证只能访问当前账号的数据。
- 本地未登录内容属于“本地暂存”，不带账号归属；首次登录迁移时才绑定到当前账号。
- 网页快照和普通附件的对象路径必须包含账号 ID，不能依赖随机文件名实现隔离。

### 三个模块接缝

`Auth`：提供注册、邮箱验证、登录、持久会话、退出当前设备、退出所有设备和密码重置。

`AccountStore`：提供当前账号、账号范围内的记录读写、本地暂存迁移和登出清理；它隐藏 localStorage/IndexedDB 的具体键名。

`Sync`：提供增量拉取、变更推送、文件上传下载和同步状态；它不负责页面渲染，也不直接操作 DOM。

### 同步规则

- 设备离线时先写入本地变更队列。
- 设备联网后按队列推送，再拉取当前账号的远端变更。
- 同一条记录冲突时，以服务端确认的最新修改时间覆盖旧版本。
- 删除使用同步墓碑而不是立即物理删除，避免其他设备重新拉回已删除记录。
- 文件数据和记录元数据分开同步；元数据先同步，文件随后后台下载。

### 技术选择

- 第一版使用用户自己持有的 Supabase 项目：Auth、Postgres 和 Storage。
- 前端只使用公开 anon key，绝不把 service role key 放进浏览器。
- Supabase 相关代码只能出现在适配器中，页面和本地模块依赖抽象接口。

## 后果

正面效果：账号隔离可以由数据库策略和本地命名空间双重保证；同步、认证和云服务可独立测试和替换；当前离线优先体验可以保留。

代价：需要维护同步队列、删除墓碑和文件状态；真实云端登录需要用户创建 Supabase 项目并配置环境变量；在没有云端配置时，应用仍必须可作为本地暂存工具运行。

## 未包含在本阶段

- 社交账号、共享记录和协作空间。
- 端到端加密。
- 多账号同时在线切换。
- 账号存储的产品层固定上限。
