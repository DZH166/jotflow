# 小董随心录 v0.2 稳定核心 Spec

## Background

v0.1 已完成文字、链接、图片、附件和网页快照的本地记录闭环，并接通 Supabase 真实账号、私有数据、附件与快照跨客户端同步。当前构建与已有测试通过，真实注册、邮箱验证、登录和双客户端同步已经验收。

现阶段的主要风险不在功能数量，而在账号范围由共享可变状态控制、同步可能重叠、文件传输阻塞记录同步、失败后缺少可靠重试，以及外部备份数据进入页面前校验不足。v0.2 先把这些基础能力做稳，同时补齐密码恢复和手机端账号入口，为下一阶段的 Android 捕捉、模糊搜索和体验优化建立可靠底座。

## Goals

- 在迁移、同步、编辑和退出同时发生时，任何账号数据都不会写入其他账号或本地暂存。
- 本地编辑不会被较早启动的同步任务覆盖，网络失败后不需要用户制造一次新编辑才能继续同步。
- 文字记录优先完成同步；单个附件或快照失败不会阻止其他记录出现。
- 删除记录和恢复备份后，旧设备或云端旧数据不会把已删除内容重新带回。
- 所有备份文件都按不可信输入处理，不能通过导入内容影响应用页面或执行脚本。
- 用户能在手机宽度下进入账号管理，并完成从找回邮件到设置新密码的完整流程。
- 为账号隔离、迁移、同步、删除和备份建立可重复运行的自动化验收基础。

## Functional Requirements

- F1：每次本地记录、附件和网页快照操作都必须使用明确的数据范围；异步操作不能依赖会在执行期间改变的“当前账号”。
- F2：同一设备同一时间只能有一个同步过程写入本地结果；同步期间产生的新编辑必须保留并在当前或下一轮同步中上传。
- F3：同步失败后必须保留待同步状态，并在网络恢复或延迟重试时自动继续；多次触发应合并，不能并行覆盖。
- F4：远端记录元数据必须先落入本地并可见，附件和网页快照随后独立下载；单个文件失败只能影响该文件，不能回滚已成功的文字记录。
- F5：删除必须保持墓碑语义。离线旧副本不能通过普通更新清除较新的删除状态；远端文件只能在删除状态已经可靠保存后清理。
- F6：移除、替换附件或删除快照后，旧云端对象必须进入可重试的清理流程，不遗留永久孤立文件。
- F7：恢复账号备份时，恢复结果必须与备份内容一致；当前云端中不在备份里的旧记录必须被可靠删除，后续同步不能重新拉回。
- F8：备份中的记录 ID、快照 ID、字段和引用必须经过严格校验或安全编码；导入后不得形成可执行 HTML、脚本或事件处理器。
- F9：密码找回必须覆盖发送邮件、识别恢复会话、输入并确认新密码、提交成功和错误反馈。
- F10：在 320px 及以上屏幕宽度，未登录用户可以进入登录/注册，已登录用户可以进入账号管理和退出操作。
- F11：已登录且在线的客户端必须在无需新增本地记录的情况下自动获取其他客户端的新变化。
- F12：项目文档必须与实际行为一致，明确 v0.2 已完成能力、仍有限制以及下一阶段范围。

## Non-Functional Requirements

- N1：账号隔离是硬性不变量；检测到范围变化时，同步结果必须被取消或写回原始范围，不能写入当前新范围。
- N2：现有本地暂存、账号缓存、附件、网页快照和 Supabase 数据必须向后兼容，不要求用户清空数据重新开始。
- N3：本地新增和编辑仍采用离线优先；没有网络时保存动作不能依赖 Supabase 成功。
- N4：同步重试必须有上限退避，避免持续快速请求；界面需要区分已同步、离线保存、正在同步和等待重试。
- N5：测试必须可在本机无真实 Supabase 密钥的情况下验证核心状态机；真实 Supabase 只用于最终集成验收。
- N6：继续支持 Windows Chrome/Edge 和 Android Chrome 的响应式页面；本版本不要求原生 Android 应用。
- N7：保持现有视觉语言，不进行整站视觉重做；功能正确性和操作反馈优先。
- N8：不得把 Supabase `service_role` key 或其他管理员密钥加入前端、测试夹具、日志或 Git。

## Out of Scope

- 正式公网部署、PWA 安装和 Android 系统分享入口。
- 浏览器扩展直接写入账号，当前下载后导入流程暂时保留。
- 模糊搜索算法重做、OCR、自动标签或 AI 分类。
- 社交分享、协作空间、多账号同时在线切换。
- 端到端加密和收费套餐设计。
- 整站视觉改版或迁移到新的前端框架。

## Acceptance Criteria

- AC1：同步进行时新增或编辑记录，最终本地和云端都保留最新内容，没有旧同步结果覆盖新编辑。
- AC2：账号 A 同步途中退出并登录账号 B，账号 A 的记录、附件和快照不会出现在账号 B 或本地暂存中。
- AC3：网络请求失败后记录保持待同步；网络恢复后 60 秒内自动继续同步，无需用户再次编辑。
- AC4：远端包含一条文字记录和一个下载失败的附件时，文字记录仍会出现在界面，附件显示可理解的失败或待重试状态。
- AC5：一个设备删除记录后，另一个持有旧副本的设备同步不能使记录复活；删除后的文件清理失败可以重试。
- AC6：移除或替换附件后，原云端对象最终被清理，新附件仍可在另一客户端下载。
- AC7：恢复只含部分记录的账号备份后，多次同步结果仍与备份一致，被排除的云端旧记录不会重新出现。
- AC8：导入包含恶意 ID、属性字符或脚本内容的备份时，应用拒绝文件或安全显示文本，页面不执行任何导入脚本。
- AC9：用户点击找回密码邮件回到应用后，可以设置新密码，并使用新密码重新登录。
- AC10：在 320px、390px 和桌面宽度下，账号入口可见且登录、注册和退出操作可完成。
- AC11：两个在线客户端保持打开时，一端新增、编辑或删除记录，另一端在 30 秒内出现相同结果。
- AC12：自动化测试覆盖 AC1 至 AC8 的核心逻辑，构建、测试和真实双账号/双客户端回归全部通过。
- AC13：README、账号同步契约、网页快照契约和 v0.2 进度说明与最终实现一致。
